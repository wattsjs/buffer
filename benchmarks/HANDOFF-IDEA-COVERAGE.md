# Handoff ideas: evidence, decisions and experiments

Checked 2026-10-05. Covers the playback foundations, recovery architecture, validation and whole-app proposals in [handoff.md][handoff] and [PLAYBACK-FOUNDATIONS.md][foundations]. Public source inspection and local binary inspection below did not launch an app, access a provider, install a dependency or build an engine. Runtime observations are identified by their existing artifacts; fresh comparison results should be added separately.

Video interruption, frame drops and CPU take priority. Keep libmpv as the compatibility baseline while qualifying its audio lifecycle, GStreamer and AVPlayer. The strongest small intervention is transport/cache recovery beneath an existing decoder; an engine change still needs feature and format coverage. Larger reserve can conceal outages by increasing live delay, so compare at an explicit delay target.

## Playback foundations

| Proposal | Evidence and current decision | Concrete experiment and tradeoff |
|---|---|---|
| libmpv CoreAudio lifecycle fix | Two retained crashes follow audio-unit initialization failure. Upstream now registers hotplug callbacks after audio initialization and calls cleanup on failure; 0.41 registered earlier and returned without that cleanup. This supports the callback-lifetime hypothesis. No patched artifact is integrated or qualified. [0.41 source](https://github.com/mpv-player/mpv/blob/v0.41.0/audio/out/ao_coreaudio.c), [pinned upstream](https://github.com/mpv-player/mpv/blob/0ea9365df8a4203d9895492eef0561bc8907283e/audio/out/ao_coreaudio.c). | Pin a patched MPVKit artifact, record dependency provenance, then test failed initialization, device notifications, stop/reuse and repeated clean/fault playback. Preserve user pause intent. An upstream source fix alone cannot establish this host's stability. |
| libmpv AVFoundation audio | Actual `current-ao` evidence exists; video continues through libmpv. Clean and fault runs include both successes and failures. Production auto/CoreAudio remains unchanged. [Historical evidence][foundations]. | Compare auto, CoreAudio and AVFoundation on the same signed optimized app and output device. Include routing, multichannel layouts, wake and source changes. It can avoid one audio path without changing demux/render compatibility; successful selected output does not prove physical audibility. |
| Native AVPlayer | Existing Cocoa probe rendered rolling HLS through AVPlayerLayer and survived one 502 burst. Apple exposes a network-based recommended live offset and a configured starting/resume offset. [Recommendation](https://developer.apple.com/documentation/avfoundation/avplayeritem/recommendedtimeoffsetfromlive), [configuration](https://developer.apple.com/documentation/avfoundation/avplayeritem/configuredtimeoffsetfromlive). | Repeat at matched reserve/delay and presentation size; test TS archive seeks, headers/redirects, malformed manifests, discontinuities, HEVC/HDR and recording. Then host it behind the same app/player contract. Native transport controls differ from a custom downloader, and probe CPU omits the rest of Buffer. |
| GStreamer transport and decode | Existing probe instantiates `hlsdemux2`, `vtdec_hw` and real audio/video sinks. `vtdec_hw` is hardware-only; `vtdec` can select software. Its advertised input includes H.264, HEVC and MPEG-2, but format support still requires actual negotiation. [Hardware decoder](https://gstreamer.freedesktop.org/documentation/applemedia/vtdec_hw.html), [general decoder](https://gstreamer.freedesktop.org/documentation/applemedia/vtdec.html). | Repeat clean/502/stall runs with negotiated caps and elements recorded, then test interlaced sports, 10-bit HEVC, multichannel audio, seek and cancellation. Codec names and hardware preference are insufficient evidence of the negotiated output or correct color. |
| GStreamer presentation path | `glimagesink` supports an application-owned drawable and GL-memory input; it is the current measured low-CPU candidate. `osxvideosink` used much more CPU on this fixture. The CALayer-producing `avsamplebufferlayersink` crashed once on this macOS beta host. [GL sink](https://gstreamer.freedesktop.org/documentation/opengl/glimagesink.html), [Apple layer sink](https://gstreamer.freedesktop.org/documentation/applemedia/avsamplebufferlayersink.html), [existing probe][gst-probe]. | Keep GL as the comparison baseline. Reproduce the Apple sink crash before revisiting it; inspect caps, copies, color metadata and resize/occlusion behavior. A Metal/custom sink needs a separate implementation and measurement; no qualified Metal GStreamer sink was established by this review. |
| KSPlayer | Public source defaults to GPL-3.0; the maintainer describes a paid LGPL edition. Disk precache, rewind and zero-delay switching are paid-edition features, while hardware deinterlacing and memory seeking differ between editions. Public package uses FFmpegKit from 6.1.4 and Metal shader resources; the feature table advertises different FFmpeg versions by edition. [Edition table](https://github.com/kingslay/KSPlayer/tree/0947b3e4d755addcea04980fe7cb4a4d92810bf2#features), [pinned package](https://github.com/kingslay/KSPlayer/blob/0947b3e4d755addcea04980fe7cb4a4d92810bf2/Package.swift). | First pin an edition/revision and inspect its actual dependency license/build options. Compile an isolated macOS arm64 host, expose hardware/frames/audio/cache counters, then run the same local corpus. Measure public functionality as shipped; paid feature claims do not establish public-package performance. No KSPlayer runtime or package integration has been tested here. |
| VLCKit/libVLC | Official macOS Objective-C wrapper is LGPL-2.1-or-later. Current SPM manifest targets macOS and references an **unstable 4.0** zip dated 2026-09-29, with a checksum. README still shows 3.3 examples. [README/license](https://github.com/videolan/vlckit/tree/2e0868f5ed40fe59cd92f377645fdcc260c6e759), [pinned package](https://github.com/videolan/vlckit/blob/2e0868f5ed40fe59cd92f377645fdcc260c6e759/Package.swift). | Inspect the exact archive's macOS arm64 slices, nested frameworks/plugins and licenses, then build a Cocoa host and test hardware decode, startup, frame stats, recovery and package size. Choose a pinned stable or experimental artifact deliberately. Broad VLC compatibility is useful, but no Buffer-side runtime result exists. |
| FFmpeg + VideoToolbox + Apple render synchronizer | Apple's synchronizer provides one timeline for queued audio/video renderers. The installed macOS 27 SDK deprecates older Swift add/remove-renderer and audio enqueue APIs in favor of receiver APIs. [Synchronizer](https://developer.apple.com/documentation/avfoundation/avsamplebufferrendersynchronizer), [audio renderer](https://developer.apple.com/documentation/avfoundation/avsamplebufferaudiorenderer). | A bounded prototype would demux on a worker, preserve timestamps, decode to CVPixelBuffer, feed video/audio receivers and handle discontinuity/flush explicitly. This offers transport control and native presentation but makes Buffer own clocks, HDR, interlacing, seeks, subtitles, device changes and lifecycle. Test synchronization before attempting a complete scheduler. Not implemented. |
| GStreamer appsink → native/Metal presentation | Appsink exposes samples and queue limits; its pull operations can block and its default queue can grow without explicit bounds. [Appsink](https://gstreamer.freedesktop.org/documentation/app/appsink.html). | Use a worker, set buffer/byte/time bounds and an explicit late-frame policy, retain GPU/pixel-buffer ownership correctly, and map the GstSegment timeline to the native clock. It may improve presentation integration but can add copies and A/V scheduling responsibility. Measure against GL before adopting. Not implemented. |
| FFmpeg libcurl beneath libmpv | Current FFmpeg documents an optional `--enable-libcurl` backend, per-format-context connection sharing and HTTP/2/3 selection. `prefer_libcurl` has no effect without that build support. [Protocols](https://ffmpeg.org/ffmpeg-protocols.html#libcurl). Pinned source retries recoverable curl errors for seekable transfers; it is not automatically equivalent to existing native-HTTP status-specific reconnect options. [Source](https://github.com/FFmpeg/FFmpeg/blob/ef52e1cc3850846987edc792c9583103e977e3b2/libavformat/libcurl.c). | Current Buffer inspection found no libcurl protocol markers; details below. Build a separate pinned FFmpeg/MPV artifact and verify protocol enumeration, option propagation into nested HLS, HTTP version, cancellation, ranges and errors. HTTP/3 requires compatible curl and server support. Potentially smaller than engine replacement; current binary support and runtime benefit are unqualified. |

Licenses above are snapshots of the inspected upstream projects, not a distribution decision. FFmpeg's resulting license depends on its configured components; inspect actual artifacts rather than substituting the framework's top-level label. [FFmpeg build/license guidance](https://ffmpeg.org/legal.html).

## Provider recovery and live-delay control

These are design conclusions and bounded experiments. Except for the explicitly identified production lifecycle changes, they remain unimplemented proposals.

| Handoff proposal | Feasibility, current status and next discriminating experiment |
|---|---|
| Separate transport policy from decoder/rendering | Keep one observable playback contract for request intent, decoded format, reserve, render activity and recovery. First compare retry/cache policy on the same libmpv renderer so a transport improvement cannot be mistaken for decoder improvement. An engine adapter should preserve archive, tracks, subtitles, stop acknowledgment and user pause semantics. |
| Classify transient 5xx/network errors, auth expiry, throttling and terminal content errors | Existing liveness helpers avoid some destructive reloads. Add local 502/503, reset, timeout, 401/403, 429/509, missing segment and corrupt payload scenarios with request counts. Bound retry time and attempt count; stop or surface actionable auth/throttle errors rather than repeatedly consuming connections. Classification requires the actual nested request result, not one log substring. |
| Preserve cached media before escalating to reload | Existing recovery/pause work preserves requested playback and viable reserve, with helper tests. Repeated local faults must demonstrate rendered continuity, bounded reserve depletion and no needless new load generation. A full reload destroys useful state and is appropriate only after cache/transport recovery is exhausted. |
| Bounded FFmpeg retry | Validation-only native HTTP options include status-specific reconnect and finite retry/delay limits. Repeat stream-only versus demux-only option runs and count nested segment requests; test pooled-player reset afterward. Promote only the effective path that reduces stalls at the same delay and avoids retrying throttling/auth failures. |
| Adaptive reserve, low-delay/balanced/resilient modes | Collect segment latency, outage duration, delivered bytes and audio/video reserve before choosing a controller. GStreamer exposes bandwidth, track reserve, time watermarks and finite retry controls. [Adaptive demux](https://gstreamer.freedesktop.org/documentation/adaptivedemux2/GstAdaptiveDemux2.html). Prototype bounded targets that rise quickly after trouble and fall slowly; compare outage survival and actual live delay. Larger buffer is a deliberate latency cost. |
| Gradual catch-up plus explicit Go Live | Once reserve is healthy, test a small bounded playback-rate adjustment with A/V, pitch, subtitle and drop counters. Reset on user pause/seek and keep Go Live explicit. Catch-up requires a reliable source-time mapping and adequate decode headroom; it cannot erase encoder delay or provider gaps. |
| Rendition adaptation | Use only a real equivalent-rendition set or HLS master playlist; measure switches at segment/keyframe boundaries. Test throughput throttling and different codecs/audio groups. A similarly named channel does not establish programme or timestamp equivalence. No production adaptation is implemented. |
| Authorized provider/feed failover | Build an explicit equivalent-feed map, verify programme/timeline compatibility, and acknowledge old backend idle before opening another provider stream. Test local alternatives first. Timestamp jumps, audio changes and account connection limits make blind URL switching unsuitable. No transparent failover is implemented. |
| Shared playback/recording segment broker/cache | A bounded local broker can deduplicate identical segment/key requests and separate cancellation of consumers. Define cache key by source/auth generation, full resource identity, byte range and encryption context; cap bytes/time and evict expired resources. Test one fetch feeding two consumers, range/key rotation and complete cancellation. It may reduce duplicate connections but adds HTTP/key/storage ownership. No broker is implemented. |
| Local HLS normalizer/remuxer | Start with one reproducible provider manifest/timestamp defect and lossless remux where supported. Preserve sequence, byte ranges, discontinuities, keys, source times and seek window. Feed the result to AVPlayer and compare latency/copies/CPU. It cannot invent absent segments, remove encoder delay or make arbitrary DRM usable. No normalizer is implemented. |

## Evidence quality and whole-app coverage

| Handoff proposal | Existing coverage | Remaining experiment or acceptance condition |
|---|---|---|
| Fair compiler/app hosts and repeated comparisons | Full signed optimized Debug/WMO app and compatible artifact metadata exist. Native/GStreamer probes are optimized standalone hosts. | Repeat matched clean and fault scenarios, record variance and both profiled/ordinary build overhead. Full-app versus small-host CPU remains contextual until engines share a comparable host. |
| Match reserve, true/estimated delay, size, bitrate and format | Local HLS harness records scenario and faults; native/GStreamer have fixture delay observations. | Use the same live origin and presentation size, record actual reserve, verify source-time mapping for libmpv and include delay in acceptance. A larger reserve must not win solely by increasing latency. |
| System CPU/GPU/power, RSS versus footprint | Process CPU/RSS and normal-app physical-footprint telemetry exist. | Measure system decoder/GPU/energy and WindowServer cost separately; take sustained distributions. RSS and physical footprint are distinct. Do not infer a leak from one peak. |
| Render, generation and audio evidence | MPV item/lifecycle correlation, actual render counters, A/V/output gates, teardown and fail-closed diagnostics are implemented and tested. | Add perceptual frozen-frame detection and non-silent channel-routing fixtures; keep native/GStreamer missing independent A/V/decoder-drop measurements explicit. Silent AAC cannot prove physical sound. Migrate the native probe's deprecated synchronous access/error logs to the macOS 27 async fetch APIs verified in the installed AVPlayerItem header, retaining availability fallback. |
| Codec/provider corpus | Local H.264 720p30/1080p60 and short saved-source SD/HD/UHD observations exist. | Add HEVC 4K50/59.94, 10-bit HDR, interlaced sports, long GOPs, truncation, bad manifests, auth redirects, timestamp gaps/discontinuities and actual archive seeks. A channel's HDR label is not color/output qualification. |
| Real sources, exact identifiers, archive provenance | Scenario runs one owned player at a time, restores source/selection and rejects ambiguous names. Initial seven-case matrix has three passes and four ambiguities. Exact-ID retry has two passes, a UHD drop/occlusion failure and an archive stall failure. [Initial matrix][matrix-initial], [retry][matrix-retry]. | Repeat failed cases with controlled visibility, retain drop/stall failures, then run sustained cases across sources/resolutions. Twenty-five seconds is startup/immediate playback coverage, not long-run qualification. |
| Pause ownership, pooled reuse, first-frame attribution and warnings | Production helpers cover intent/cache/background/system pause and actual MPV entry lifecycle. | Actual repeated zapping, background focus, network interruption and stop/reopen must show no stale generation, unsolicited resume or leaked validation options. Helper tests do not qualify the entire runtime path. |
| Long runs, multiview, recording, wake and device changes | Existing single-player observations and lifecycle helpers provide a foundation. | Run sustained workloads, then controlled multi-view/recording and wake/device scenarios without exceeding provider limits. Observe every slot, primary audio, render activity and resource growth. |
| Source-switch cancellation, catalogue/guide overlap and VOD | Production integration tests cover epochs, cancellation, partial/failed catalogues, disabled VOD, preference revisions and cache identity. [Aggregate log][aggregate]. | Verify source switches and enabled/disabled VOD in the actual app during playback, including stale detail completions and credential edits. Synthetic loopback success is not provider/UI qualification. |
| EPG lookup, scrolling, metadata and timeline | Prepared lookups have 311,902 differential checks; grid and history tests include sparse coverage, bounds and hundreds of thousands of listings. Viewport-backed cards fixed the reproduced compositor failure; dark UI has actual screenshot evidence. | Validate current/replay titles, pan/hit testing, group/favorite changes, same-ID metadata, large real guides and final title pinning in the current binary. Retain cached real history through failing refreshes; never fill gaps with unrelated listings. |
| Cold/warm hydration and repeated memory lifetime | Cache writes/identity, parser/image bounds, index cancellation and sports rebuild coalescing are tested. | Sustained real refreshes during video must show bounded retained generations and responsive main-thread commits. Compare cold/warm latency and footprint separately; initial cache migration can be cold. |
| Sports fixtures, polling, matching and refresh lifecycle | Request concurrency, cancellation, index/card invalidation and hidden disclosure tests pass. A real empty Sports screen triggered a current endpoint/error-path repair. | Validate actual nonempty fixture refresh and error presentation in the combined build, plus refresh/source bursts during video. Successful empty decoding cannot conceal a rejected endpoint. |
| C/low-level changes guided by measurement | Stable channel identity encoding uses a tested native digest path; Swift interval/index/cache work has fixture evidence. | Use profiles to identify the remaining dominant cost before introducing more C or a new module boundary. A lower-level implementation is worthwhile only with equivalent output and measured whole-workload benefit. |
| Stable automation and reproducibility | Saved-source scenario driver, artifact fingerprints, short budgets, exact selectors and asynchronous diagnostic output exist. [Matrix tests][matrix-tests], [transport tests][transport-tests]. | Complete final combined-build checks and runtime captures. Record failure, malformed output and lost records explicitly; retain controlled fault negative cases. |
| Local build/signing, source availability and privacy | Stable certificate requirement is pinned; collectors avoid provider URLs/configuration dumps and confirm backend idle before advancing. | Reuse the existing identity and one provider player. Verify the exact rebuilt artifact; do not recreate the certificate or run legacy credential-bearing/broad-kill scripts. |

## Local libcurl inspection and reproducibility

The inspected optimized main executable was 53,118,640 bytes, SHA-256 `2226f3721960a27dd5581ff0d5ac35dbf613800db17dac2a4479982d0fa0035c`. It contained `Lavf62.3.100`, `_avio_enum_protocols`, `_avformat_configuration` and `_mpv_client_api_version`, but no `prefer_libcurl`, `ff_libcurl_protocol`, `curl_multi_init` or `--enable-libcurl` token/symbol. The embedded Libavformat/Libmpv framework executables were approximately 51 KB wrappers and did not contain those FFmpeg functions. This is evidence against current libcurl inclusion, **not a runtime protocol enumeration**. A future rebuilt artifact must be checked independently; the fixture-generating CLI FFmpeg is a separate build.

Primary code revisions inspected: KSPlayer `0947b3e4`, VLCKit `2e0868f5`, FFmpeg `ef52e1cc`, mpv `0ea9365d`. Apple documentation JSON and the installed macOS 27 AVFoundation headers were read to check synchronizer/receiver APIs. The proposed order is audio correctness and comparable clean/fault playback first, then corpus and reserve experiments, then alternate wrappers or custom transport/rendering where a measured gap remains.
